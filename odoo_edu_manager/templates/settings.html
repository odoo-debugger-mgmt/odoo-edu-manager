Open in editor

Each instance has two buttons: VS Code (the desktop app) and code-server (in the browser). Both open the same generated multi-root .code-workspace — Odoo core, Enterprise/themes if included, every addons folder, plus a debugpy attach config when debug is on.

The desktop button is always {{ vscode_example }}, since that is simply what the URL handler is. Only the browser target is configurable, so you can point it at the managed container below, a code-server elsewhere, or a tunnel.

Managed code-server

A container this app owns, the same way it owns the shared Postgres container. It mounts data/ at its own absolute path and uses host networking, so generated workspaces and the debugger's localhost attach both resolve exactly as they do for the desktop app — no workspace rewriting needed.

The Python and debugpy extensions are installed automatically when the container is first created — without them the generated attach config fails with "Configured debug type 'debugpy' is not supported". Both come from Open VSX, so nothing is sideloaded. Use the reinstall button if they go missing.

Notes

  • Paths must match. The workspace file refers to absolute paths on this host. Run code-server directly on this host and they resolve as-is. If you run it in a container, mount the same directories at identical paths — every addons folder currently lives under the manager's own data/ directory, so one mount of that covers them.
  • The debugger. The attach config points at localhost:<debug port>, which works for local VS Code and for code-server running on this host. From inside a container, localhost is that container — you would need to attach to the instance container by name on odoo-manager-net instead.
  • If you translate paths for a container setup, rewrite pathMappings.localRoot as well as folders. localRoot is "as the editor sees it"; leave it pointing at old paths and the workspace opens fine while breakpoints silently never bind.
